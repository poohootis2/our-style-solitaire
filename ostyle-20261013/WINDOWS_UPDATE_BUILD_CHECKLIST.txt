OUR STYLE SOLITAIRE
Windows 최신 ZIP 동기화 및 APK/AAB 빌드 반복 절차

이 파일은 업데이트할 때마다 처음부터 끝까지 순서대로 사용합니다.

[0. 가장 중요한 원칙]

1) Manus에서 최신 ZIP을 먼저 다운로드합니다.
2) Windows 작업 폴더는 E:\game_make\our-style-solitaire4 를 사용합니다.
3) ZIP에서 app, lib, assets 폴더만 Windows 작업 폴더에 복사합니다.
4) android 폴더 전체, android\app\upload-keystore.jks, android\app\build.gradle, app.config.ts, package.json, pnpm-lock.yaml, .env 파일은 무심코 덮어쓰지 않습니다.
5) 단, 버전 업데이트가 필요한 경우에는 app.config.ts와 android\app\build.gradle의 버전을 각각 직접 확인·수정합니다.
6) upload-keystore.jks는 절대 삭제·교체·이름 변경하지 않습니다. 비밀번호와 키 파일은 채팅이나 스크린샷에 기록하지 않습니다.
7) 빌드 전에는 반드시 기존 APK의 날짜·크기와 새 소스 파일의 날짜를 비교합니다.

[1. 최신 ZIP 다운로드]

Manus 프로젝트 화면에서 최신 체크포인트 또는 최신 ZIP을 다운로드합니다.
다운로드한 ZIP의 파일명과 다운로드 시간을 확인합니다.
ZIP을 바로 Windows 빌드 폴더 전체에 덮어쓰지 않습니다.

[2. Windows 작업 폴더 확인]

PowerShell을 열고 다음 명령을 실행합니다.

cd "E:\game_make\our-style-solitaire4"
Get-Location
Test-Path ".\android\app\upload-keystore.jks"
Test-Path ".\android\app\build.gradle"

마지막 두 명령이 모두 True인지 확인합니다.
False가 나오면 빌드를 중단하고 서명키 또는 Android 설정을 먼저 복구합니다.

[3. ZIP 압축 해제]

예를 들어 ZIP을 E:\game_make\our-style-solitaire-lastzipfile 에 압축 해제했다고 가정합니다.
압축 해제 폴더에 다음 항목이 있는지 확인합니다.

Test-Path "E:\game_make\our-style-solitaire-lastzipfile\app\(tabs)\index.tsx"
Test-Path "E:\game_make\our-style-solitaire-lastzipfile\lib\solitaire.ts"
Test-Path "E:\game_make\our-style-solitaire-lastzipfile\assets\images"

모두 True여야 합니다.

[4. 최신 소스 3개 폴더만 복사]

다음 명령으로 app, lib, assets만 복사합니다.
복사 원본 경로가 실제 ZIP 압축 해제 폴더와 맞는지 먼저 확인합니다.

$src = "E:\game_make\our-style-solitaire-lastzipfile"
$dst = "E:\game_make\our-style-solitaire4"
robocopy "$src\app" "$dst\app" /E /COPY:DAT /R:2 /W:2
robocopy "$src\lib" "$dst\lib" /E /COPY:DAT /R:2 /W:2
robocopy "$src\assets" "$dst\assets" /E /COPY:DAT /R:2 /W:2

robocopy 결과에서 ERROR가 0인지 확인합니다.
파일을 복사한 뒤에는 Windows 작업 폴더의 파일을 확인합니다.

cd "E:\game_make\our-style-solitaire4"
Select-String -Path ".\app\(tabs)\index.tsx" -Pattern "directionAngle|monsterMotion|HAMMER_PLUS_ONE_BUTTON_ART|CompanionAnchor|망치"

[5. 버전 번호 확인 및 수정]

Google Play Console에 이미 등록된 버전보다 큰 versionCode를 사용합니다.
현재 기준은 다음과 같습니다.

app.config.ts:
version: "1.7.9"
android.versionCode: 34

android\app\build.gradle:
versionCode 34
versionName "1.7.9"

확인 명령:

Select-String -Path ".\app.config.ts" -Pattern "version:|versionCode:"
Select-String -Path ".\android\app\build.gradle" -Pattern "versionCode|versionName"

두 파일의 값이 서로 다르면 빌드하지 않습니다.
새 Play 업로드마다 versionCode는 반드시 이전 업로드보다 1 이상 커야 합니다.
versionName은 사용자에게 보이는 버전이고, versionCode는 Play Console이 업데이트를 판별하는 숫자입니다.

[6. 서명키 확인]

서명키 파일이 있는지 확인합니다.

Test-Path ".\android\app\upload-keystore.jks"
keytool -list -v -keystore ".\android\app\upload-keystore.jks" | Select-String "Alias name|SHA1"

기존 Play Console 업로드 키와 동일한 SHA1인지 확인합니다.
현재 작업에서 확인한 업로드 키 SHA1은 다음과 같습니다.
BA:3E:1F:46:2A:60:2F:4C:D2:D0:1C:87:5A:51:84:17:8C:B7:CA:BF

SHA1이 다르면 빌드·업로드를 중단합니다.
서명 설정은 android\app\build.gradle의 release signingConfig가 signingConfigs.release를 사용하는지 확인합니다.
release가 signingConfigs.debug를 사용하면 Google Play 업로드용으로 사용하지 않습니다.

[7. 빌드 폴더 정리]

소스가 최신으로 복사되고 버전·서명키가 확인된 뒤 Android 폴더로 이동합니다.
clean과 Release 빌드는 반드시 분리해서 실행합니다.

cd "E:\game_make\our-style-solitaire4\android"
.\gradlew.bat clean
.\gradlew.bat :app:assembleRelease
.\gradlew.bat :app:bundleRelease

clean은 서명키를 삭제하지 않습니다.
다만 clean과 assembleRelease를 한 줄에서 동시에 실행하지 않습니다.
빌드 중 오류가 나면 같은 명령을 무작정 반복하지 말고 오류의 첫 원인부터 확인합니다.

[8. APK 파일 날짜와 버전 확인]

APK가 방금 생성되었는지 확인합니다.

$a = ".\app\build\outputs\apk\release\app-release.apk"
Get-Item $a | Select-Object FullName,Length,LastWriteTime

Android SDK의 aapt 경로가 다를 수 있으므로 실제 build-tools 버전을 사용합니다.

$aapt = "$env:LOCALAPPDATA\Android\Sdk\build-tools\36.0.0\aapt.exe"
& $aapt dump badging $a | Select-String "package: name|versionCode|versionName"

여기에 com.app.ourstylesolitaire, versionCode 34, versionName 1.7.9가 표시되어야 합니다.
생성 시간이 이전 APK와 같거나 더 오래되었으면 설치하지 말고 빌드 산출물부터 다시 확인합니다.

[9. 휴대폰 설치 전 확인]

휴대폰을 USB로 연결하고 USB 디버깅을 허용합니다.

adb kill-server
adb start-server
adb devices

List of devices에 실제 기기가 device 상태로 표시되어야 합니다.

기존 앱을 완전히 지우고 새 APK를 설치하려면 다음을 실행합니다.

adb uninstall com.app.ourstylesolitaire
adb install ".\app\build\outputs\apk\release\app-release.apk"

설치 후 실제 설치 버전을 확인합니다.

adb shell dumpsys package com.app.ourstylesolitaire | findstr /i "versionCode versionName codePath sourceDir"
adb shell pm path com.app.ourstylesolitaire

versionCode와 versionName이 빌드 파일과 같은지 확인합니다.
이 값이 다르면 휴대폰에 이전 APK가 설치된 것이므로 게임 화면만 보고 판단하지 않습니다.

[10. AAB 업로드 전 확인]

AAB 파일이 새로 생성되었는지 확인합니다.

$b = ".\app\build\outputs\bundle\release\app-release.aab"
Get-Item $b | Select-Object FullName,Length,LastWriteTime

AAB의 versionCode·versionName은 bundletool로 확인합니다.
bundletool JAR 경로는 실제로 존재하는 파일을 사용합니다.

$bundletool = Get-ChildItem "$env:USERPROFILE\.gradle\caches" -Recurse -Filter "bundletool*.jar" | Sort-Object LastWriteTime -Descending | Select-Object -First 1 -ExpandProperty FullName
java -jar $bundletool dump manifest --bundle=$b | Select-String "versionCode|versionName|AD_ID|APPLICATION_ID"

bundletool JAR에 기본 Manifest 속성이 없다는 오류가 나오면 그 파일은 실행용 bundletool이 아닐 수 있습니다.
이 경우 검증을 중단하고 공식 bundletool-all JAR을 별도로 준비한 뒤 그 경로를 직접 지정합니다.

[11. 광고 ID 확인]

AAB 또는 APK 검증 결과에 아래 항목이 있어야 합니다.

com.google.android.gms.permission.AD_ID
com.google.android.gms.ads.APPLICATION_ID
ca-app-pub-1567553177387474~9687767806

광고 단위 ID와 앱 ID는 서로 다른 값입니다.
앱 ID는 APPLICATION_ID 메타데이터에 사용하고, 광고 단위 ID는 배너·보상형 광고 코드에서 사용합니다.
Play Console에서 광고 관련 경고가 나오면 과거 활성 아티팩트가 아니라 이번 versionCode의 AAB를 검사했는지 먼저 확인합니다.

[12. Google Play Console 업로드]

APK가 실제 기기에서 실행되고 최신 화면과 기능이 확인된 후에만 AAB를 업로드합니다.
업로드 전에 다음을 다시 확인합니다.

1) versionCode가 이전 업로드보다 큽니다.
2) versionName과 versionCode가 app.config.ts·build.gradle·AAB에서 일치합니다.
3) upload-keystore.jks의 SHA1이 Play Console 요구 키와 일치합니다.
4) 광고 ID와 AD_ID 권한이 이번 AAB에 들어 있습니다.
5) 실제 기기에서 앱이 즉시 종료되지 않고 최신 UI가 표시됩니다.

[업데이트할 때마다 수정할 부분]

기능 업데이트: 최신 ZIP에서 app·lib·assets만 다시 복사합니다.
버전 업데이트: app.config.ts와 android\app\build.gradle의 두 버전을 함께 변경합니다.
서명 설정: upload-keystore.jks와 release signingConfig를 유지합니다.
빌드: clean, assembleRelease, bundleRelease를 각각 순서대로 실행합니다.
검증: 파일 생성 시간, aapt 버전, adb 설치 버전, AAB manifest를 모두 확인합니다.

[절대 하지 말아야 할 것]

android 폴더 전체를 최신 ZIP으로 덮어쓰지 않습니다.
upload-keystore.jks를 삭제하거나 다른 키로 교체하지 않습니다.
서로 다른 프로젝트 폴더에서 gradlew를 실행하지 않습니다.
버전 번호를 빌드 후에 수정하지 않습니다.
이전 APK를 새 APK로 착각하지 않습니다.
서명키 비밀번호를 메모장·스크린샷·채팅에 저장하지 않습니다.

[현재 요청 반영]

몬스터 이름·체력게이지는 이전 보정 위치에서 오른쪽으로 15px 추가 이동했습니다.
최신 소스를 Windows에 복사한 뒤 실제 기기에서 오른쪽 경계와 텍스트 잘림 여부를 반드시 확인합니다.
TXT 파일은 메모장으로 열어 복사하거나 Windows 프로젝트 폴더에 보관해 반복 사용합니다.
